# MRI research protocol (MRI-001)

## Question and preregistered decisions

Can probabilities of market regimes filtered with information available at session `t` improve forecasts of SPY risk over the next 5 or 20 US equity sessions? The null hypothesis is no reduction in mean out-of-sample QLIKE for variance forecasts and no reduction in mean Brier score for high-volatility event probabilities versus the best prespecified conventional baseline. An improvement is exploratory unless its paired uncertainty interval excludes zero on the untouched final period. A failed or inconclusive result is a valid result. No return or trading-performance claim follows from risk forecast quality.

Before any model evaluation, freeze dataset snapshot, adjustment convention, session calendar, feature and target code, horizons, retraining frequency, baseline set, threshold rule, hyperparameter grid, seeds, fold boundaries, uncertainty method, and primary comparisons in a versioned experiment config. Log all attempted variants. Do not inspect final-period outcomes while selecting models.

## Universe and data

Primary universe: SPY, one US-listed ETF, daily exchange sessions from 2005-01-01 through the latest *completed* session available from a documented provider snapshot. Dataset coverage, corporate-action adjustment, publication timing, outages, source revisions and rights must be audited. A single surviving ETF cannot establish generality to other assets or a historical investable equity universe. Calendar is XNYS sessions, not weekdays. Store source bytes, retrieval UTC time, request parameters, SHA-256, provider identity, processing version and validation report. The initial Stooq adapter is a research-data source; its adjusted OHLC convention is an explicit provider assumption requiring independent verification before financial conclusions. No historical `available_at` is supplied by this source, so current download timestamps cannot prove point-in-time availability.

## Features and timing (MRI-004 scope)

At close of session `t`, with a consistent adjusted-close series `P_t`, define log return `r_t = ln(P_t/P_(t-1))`; 20-session realized volatility `sqrt(252/20 * sum_(i=0..19) r_(t-i)^2)` (annualized, uncentered); 20-session momentum `ln(P_t/P_(t-20))`; 60-session drawdown `P_t/max(P_(t-59)..P_t)-1`. Require complete windows; never backfill. HMM's initial inputs are `r_t` and 20-day realized volatility only; momentum and drawdown require separate ablations. Features and preprocessing parameters are computed per training fold; any transform fitted on data uses training observations only. A signal based on close `t` is first actionable after that close. A data source with later publication requires a correspondingly later decision time.

## Targets (MRI-004 scope)

For horizon `h in {5,20}` sessions, forward realized **daily variance** `V_(t,h) = (1/h) * sum_(j=1..h) r_(t+j)^2`; annualized forward volatility `sigma_(t,h) = sqrt(252 * V_(t,h))`. QLIKE uses `V_(t,h)` and a strictly positive predicted daily variance, with `L = log(vhat) + V/vhat`; differences of QLIKE are meaningful even when realized variance is zero. Volatility MAE/RMSE compare annualized `sigma`. Define event `Y_(t,h)=1[sigma_(t,h)>q_(h,0.90)]`, where `q` is the 90th percentile of *fully observed training-window targets* at that fit origin. Freeze the threshold for the next prediction block and record it; do not estimate it using validation or final labels. This yields a training-relative event, not a fixed physical volatility level.

## Models and evaluation (future scope)

Baselines: historical variance over trailing 20 sessions, EWMA variance with a prespecified decay grid fitted/selected on development data, and GARCH(1,1) with documented innovation distribution and estimation diagnostics. Candidate: Gaussian HMM with 2–4 states, returns plus realized volatility, trained only on past windows; forecast from **filtered** state probabilities at `t`, never smoothed posterior states from future observations. Map states across fits by an explicit risk ordering and report instability. Regime-conditioned variance and event forecasts must use training-only estimates and probability calibration. No model is implemented in MRI-001 through MRI-003.

Proposed date bands: 2005–2015 development; 2016–2020 validation for model choice; 2021 onward untouched final evaluation. Use expanding training windows, monthly retraining at the first trading session of each calendar month (fixed before evaluation), and daily forecast origins after complete features are available. Model selection happens only in development/validation; select one specification per horizon/target before final evaluation. At each origin, training labels must end by the last observable session. Purge any label whose interval `(t,t+h]` crosses a fit, validation, or test boundary. For validation-model selection, do not let labels ending in validation enter training; similarly for final. Treat pending labels as unavailable even when their origin is in training. Refit only with subsequently matured labels. Record exact session indices and split boundaries, including any embargo used for overlapping outcomes.

## Scores, uncertainty and calibration

Primary: mean QLIKE for variance and Brier score `(p-Y)^2` for event probability, paired against each baseline on identical forecast origins. Report raw means and paired differences by horizon, with counts and intervals. Secondary: volatility MAE/RMSE; event log loss with prespecified probability clipping; ROC-AUC and PR-AUC only when both classes exist; reliability diagrams, calibration slope/intercept and event rates; regime dwell times, transition stability and sensitivity to initialization. Align units before scoring. Overlapping 5/20-session labels create serial dependence; use a paired moving-block bootstrap over chronological forecast origins with block length at least the longest horizon (20 sessions), prespecified repetitions/seed, and sensitivity to longer blocks. Report interval estimates rather than naive IID tests. Correct or clearly label multiple model/horizon comparisons; final inference is limited to the frozen primary comparisons. No significance claim from validation tuning.

## Leakage controls and reproducibility

Check `observed_at`, `available_at`, `ingested_at`, and decision time separately when the source supports them. Enforce chronological sort, unique XNYS dates, consistent adjustment, complete rolling windows, no future rows in training transforms, filtered HMM probabilities, training-only event thresholds, matured labels, purge at boundaries, and untouched final holdout. Assert these in leakage tests before research runs. Every run logs code commit and dirty status, source hashes/manifests, config, package lock, calendar version, OS/Python, random seeds, split indices, model diagnostics, predictions, failures and all attempted variants. Archive immutable inputs and machine-readable outputs; a hash proves byte identity, not causal or financial validity.

## Decision criteria and limits

Scientific success: on the frozen final period, a regime model has lower paired QLIKE and/or Brier than the selected conventional comparator with a dependence-aware interval excluding zero, stable calibration, and no material leakage audit failure. Otherwise report no demonstrated improvement. Results remain specific to SPY, provider vintage, era and evaluation choices; structural shifts, ETF distributions, provider revisions, transaction costs (if later applied to trading), model identification and multiple testing limit interpretation. Synthetic fixtures verify software behavior only.
