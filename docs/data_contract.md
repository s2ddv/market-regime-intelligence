# Daily market data contract (MRI-001)

Canonical daily table has exactly one row per XNYS session and symbol, sorted ascending by `date` (session date, ISO `YYYY-MM-DD`, timezone-free). `open`, `high`, `low`, `close`, `adjusted_close` are finite positive USD/share float64; `volume` is finite nonnegative shares float64 (integral values when provider supplies them); `symbol` is `SPY`; `source` identifies provider. No implicit forward fill, interpolation, or duplicate resolution. Missing sessions are checked against XNYS between requested bounds and reported as errors. Partial first/last provider coverage is also an error unless requested bounds are narrowed explicitly.

Timestamp metadata: request start/end are XNYS session dates; `retrieved_at` is an aware UTC timestamp when bytes were obtained; `ingested_at` is UTC processing time. `observed_at` is market observation time and `available_at` is publication time only when source evidence supplies them. A daily date is not equivalent to either timestamp. Latest completed session must be selected from the exchange calendar and current time, never from the wall-clock date alone.

Adjustment policy for initial Stooq adapter: source is assumed to publish split/dividend-adjusted OHLC; set `adjusted_close = close` and record `price_basis=adjusted_ohlc`, `adjustment_verified=false`. Because Stooq does not deliver separate raw and adjusted OHLC in this endpoint, raw prices must not be inferred from adjusted ones. The canonical columns are interpreted according to manifest `price_basis`; downstream returns use `adjusted_close` only. A provider offering raw OHLC plus adjusted close must use `price_basis=raw_ohlc_adjusted_close`, keep raw OHLC unchanged, and document split/dividend factors. Validation requires adjusted close equal close for `adjusted_ohlc`, and rejects unknown/mixed conventions; OHLC inequalities are checked only among same-basis OHLC fields. Source revisions and action factors need independent audit before financial claims.

Raw snapshot: exact provider response bytes (`.csv`) and JSON metadata with provider, symbol, requested dates, retrieval UTC, request URL (no secrets), response SHA-256 and schema version. Processed dataset: Parquet with canonical column order. Manifest records raw/processed hashes, row count, min/max dates, provider, price basis, adjustment verification, calendar, retrieval/ingestion UTC, request bounds, processing version and validation summary. Existing paths are never overwritten; conflicting writes fail. Reload checks both hashes and revalidates the canonical table. No dataset or credentials in Git.

Reject invalid schema or types; duplicate, unordered or non-session dates; non-finite/nonpositive prices; negative/non-finite volume; `high < max(open,close,low)` or `low > min(open,close,high)`; inconsistent `adjusted_close` for adjusted OHLC; and absent expected XNYS sessions. Provider outage and incomplete coverage are errors, not zero returns. Calendar version and timezone should be pinned in the lockfile.
