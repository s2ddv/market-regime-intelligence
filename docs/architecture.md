# Architecture (MRI-001)

Data flow: provider adapter -> immutable raw snapshot and metadata -> parse into canonical daily schema -> calendar/price/adjustment validation -> content-addressed Parquet plus manifest -> causal features and separate forward targets -> fold-specific models -> forecasts -> aligned scores -> report. MRI-005 adds a training-only Gaussian HMM and a frozen-parameter forward filter. MRI-006 adds monthly fold planning and restricted training-label access; neither stage runs historical scoring.

`mri.data` owns provider I/O, parsing, validation, calendar checks and persistence. Provider adapters return source bytes plus request metadata; downstream code receives canonical typed frames, never provider-specific columns. `mri.features` owns deterministic, unit-tested transforms and keeps forward labels separate from features; it does not certify point-in-time source availability. `mri.models` now owns a diagonal Gaussian HMM fit and forward filter; baseline volatility models remain future work. `mri.forecasting` will map information at an origin to horizon-specific variance and event probabilities; `mri.evaluation` owns monthly split/purge planning and gated training-target access, with metrics and uncertainty still pending; `mri.experiments` will record frozen configs, seeds, artifacts and attempted variants; `mri.reporting` will render auditable reports. The HMM has no forecasting or scoring interface yet.

Planned interfaces: a model `fit(train_features, train_targets, config, seed)` returns fitted state and diagnostics; `predict_as_of(origin_features, horizon)` returns positive daily variance and/or calibrated event probability plus provenance. A regime model must expose `filter_as_of` based on observations no later than the origin. MRI-006 now supplies explicit fit/prediction indices, label maturity cutoff and purge audit; these forecast interfaces remain design contracts.

Data fetch is an explicit command. Offline loading uses saved snapshots; no import triggers network I/O. Snapshot names and manifests are content-addressed, and writes are exclusive. Dataset files, snapshots and reports are ignored by Git.
