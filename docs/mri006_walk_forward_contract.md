# MRI-006 — walk-forward planning and label gates

Status: contract frozen before implementation, 2026-11-16; planner implemented and checked with synthetic data, 2026-11-17. This stage plans folds and protects target access; it does not score forecasts or open the final holdout.

## Objective, hypothesis and baseline

Engineering hypothesis: given validated consecutive XNYS features and a maturity-only table, a deterministic planner can produce monthly expanding-prefix refits, chronological prediction blocks, explicit label eligibility and phase sealing without reading target values. Baseline: hand-enumerated small calendars around month and phase boundaries. Acceptance: first session of each month starts a block; fit ends at previous close; prediction origins are after fit; only fully matured labels ending before both fit and protected phase are eligible; changes in validation/final target values cannot alter the plan or training event thresholds; malformed maturity dates, gaps and insufficient training fail closed.

## Frozen temporal rules

Validation clarification (2026-11-17): `min_training_sessions` counts complete return/volatility observations in the development prefix, excluding initial warm-up. The planner uses the same readiness rule as the HMM: only leading missing volatility is warm-up, infinities and negative volatility are always invalid, and missing values after warm-up are rejected. Prediction rows never permit warm-up. The minimum is checked before creating the first fold; later expanding prefixes add only validated complete rows. This guarantees input readiness, not convergence or valid state occupancy for a particular fitted model. Regression acceptance includes exact-minimum and one-short histories, invalid development values, and the prior 61-row/41-complete-observation counterexample.

Default bands are development through 2015-12-31, validation 2016-01-01 through 2020-12-31, final from 2021-01-01. The actual boundary is the first XNYS session in each band. Each validation/final calendar month has one refit just before its first observed session; the feature training prefix ends at the previous session. Prediction origins are every session in the month with complete initial HMM features. A refit during validation may observe earlier validation **features** as they arrive but cannot train a supervised mapping or threshold on validation **labels**. A final refit may use fully matured development and validation labels ending before the final boundary, while final labels stay sealed. This is a local conservative policy for model selection and final isolation.

For origin index `i` and horizon `h`, label maturity is exactly index `i+h`. A label is eligible at a fold only if its origin is before the protected phase, its maturity index is at most the fit-end index, and its maturity date is strictly before the protected phase start. Thus labels crossing the fit or phase boundary are purged. The plan receives only date and `label_end_session_h` columns; it never receives forward variance/volatility values. The threshold helper reads only eligible `forward_volatility_h` rows, computes the 90th percentile and records the resulting threshold per fold. It rejects empty, non-finite or misaligned targets. An embargo of zero sessions is recorded: strictly forward training and explicit maturity purging are the chosen controls for this scheme. Longer embargoes and alternate schedules require a new preregistration.

This planner does not enforce source `available_at`, since MRI-003's initial source lacks historical publication metadata. A close-based feature is only usable after the close and actual publication. Training on full final features in advance, viewing final labels during model selection, or using model parameters fitted after a prediction origin would violate this contract. MRI-007 onward must bind a source manifest, config, attempt log, model choices and forecast provenance to each run before any real evaluation.
